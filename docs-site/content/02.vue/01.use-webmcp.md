# Register One Tool with `useWebMCP`

Use `useWebMCP` when one Vue component owns one tool. The composable starts after
the component mounts, keeps reactive callbacks current, and cleans up when the
component unmounts.

## Usage

```vue [src/components/OrderTool.vue]
<script setup lang="ts">
import { useWebMCP } from 'vue-webmcp-tool'

const { supported, registered, error } = useWebMCP({
  name: 'lookup-order',
  description: 'Look up an order by its public identifier.',
  inputSchema: {
    type: 'object',
    properties: { id: { type: 'string' } },
    required: ['id'],
  },
  execute: async (args, { signal }) => {
    if (!args || typeof args !== 'object' || !('id' in args) || typeof args.id !== 'string') {
      throw new TypeError('id must be a string')
    }
    const response = await fetch(`/api/orders/${encodeURIComponent(args.id)}`, { signal })
    if (!response.ok) throw new Error('Order lookup failed')
    return response.json()
  },
})
</script>

<template>
  <p v-if="!supported">WebMCP is unavailable.</p>
  <p v-else-if="registered">Order lookup is available to the model.</p>
  <p v-else-if="error">Registration error: {{ error.message }}</p>
</template>
```

## Exact signature and return value

```ts
import type { MaybeRefOrGetter } from 'vue'
import type {
  UseWebMCPConfig,
  UseWebMCPOptions,
  UseWebMCPState,
} from 'vue-webmcp-tool'

function useWebMCP<TArgs = unknown, TResult = unknown>(
  options: MaybeRefOrGetter<UseWebMCPOptions<TArgs, TResult>>,
  config?: UseWebMCPConfig,
): UseWebMCPState
```

::note{icon="i-lucide-info"}
**Flexible input.** `options` can be a plain object, a Vue ref, or a getter.
The optional config is for environment injection; omit it for the real browser
environment. The returned refs update with controller snapshots and are not
booleans or a promise.
::

## Reactive options

The composable accepts reactive options. You can pass a ref or getter to update
the tool configuration dynamically.

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { useWebMCP } from 'vue-webmcp-tool'

const toolName = ref('my-tool')

const { supported, registered } = useWebMCP({
  name: toolName,
  description: 'A reactive tool.',
  execute: () => 'ok',
})
</script>
```

::important{icon="i-lucide-refresh-cw"}
**Callback vs metadata changes.** Updating only `execute`, `formatOutput`, or
`onError` does NOT re-register the tool. The browser wrapper calls the latest
callback. Changing `name`, `description`, `inputSchema`, or `annotations` DOES
trigger re-registration. Schema and annotation objects with equal JSON
serialization retain the existing registration.
::

## Lifecycle

::steps{icon="i-lucide-list-ordered"}

### Mount

The composable starts the controller in `onMounted`. Discovery begins.

### Active

The tool is registered and available to agents. Callbacks are kept current.

### Unmount

The composable stops and cleans up the controller in `onUnmounted`.

::

Each component should choose unique tool names for the tools it owns. Unmounting
stops and cleans up this composable's controller.

::warning{icon="i-lucide-shield-alert"}
**Validate input.** `inputSchema` documents the input but does not validate it.
Validate the actual argument at the start of every callback, and perform
authorization there too.
::

## Return value

The composable returns `UseWebMCPState` with these properties:

| Property | Type | Description |
|----------|------|-------------|
| `supported` | `Ref<boolean>` | Whether WebMCP is available |
| `registered` | `Ref<boolean>` | Whether the tool is registered |
| `error` | `Ref<Error \| null>` | Any registration error |
